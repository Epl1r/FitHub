# FitHub — мини-приложение Telegram

Полная карта проекта (облачная функция, бот, оплаты, хранилище, статистика) — в закрытом репозитории
Epl1r/FitHub-server, файл CLAUDE.md. Перед утверждениями про бота или сервер — читать код там.

## Этот репозиторий
- `index.html` — всё приложение одним файлом (HTML, CSS, JS). Публикуется GitHub Pages: https://epl1r.github.io/FitHub/
- `privacy.html` — политика конфиденциальности.

## Устройство index.html
- Вкладки: `tab-home`, `tab-cal`, `tab-train`, `tab-food`, `tab-profile`; нижнее меню `nav [data-tab]`.
  Порядок в меню: Главная, Питание, Арни, Тренировка, Профиль.
- Путь новичка. Вопросы (`openOnb`): 1) цель, 2) пол/возраст/рост/вес, 3) опыт, где, дни; ограничения и время свёрнуты
  в `#onbMore` со строкой-итогом (`onbMoreSum`, по умолчанию «без ограничений · 18:00»). 4) «План готов»: если тренировок ещё
  не было — «Когда первая тренировка?» (`#onbWhen`: «Сейчас» или день ближайшей недели) и главная кнопка `#onbTry`:
  «▶ Начать первую тренировка» → `onbFinish(true)` → вводная `startWorkout(camMode, true)`; день → задача «🏋️ Первая
  тренировка · вводная» в `dayTasks` на этот день (`fithub_first_day`); ниже — «Позже — открыть приложение».
  Вводная (`introItems`): первые 4 упражнения дня, не больше 2 подходов (~10 мин); во вкладке «Тренировка» пока не было
  ни одной тренировки — ссылка `#thIntro` «Впервые? Начните с вводной». Сервер узнаёт `trained` из `remPost` и через сутки
  без тренировок один раз пишет «первая тренировка ждёт».
- «Первые шаги» `#fsCard` на главной — первые 14 дней после `fithub_first_seen`, пока не выполнено всё и не скрыто (✕,
  `fithub_fs_hide`): план, первая тренировка (сразу вводная), фото еды (только переход во вкладку «Питание» с подсветкой «Добавить еду», камера и файлы сами не открываются; отметка `fithub_fs_photo` при ai_ok), спросить Арни
  (`fithub_fs_chat`), напоминания. Это переходы в другие вкладки, функции на главную не переносятся.
- Главная не повторяет функции других вкладок (тренировки, питание и добавление задач — только в своих вкладках / в календаре).
  Сверху вниз: шапка «План на сегодня» `#dayCard` (дата, статус «Впереди N задач / Готово N из M / Всё выполнено»,
  пропущенные по времени, кольцо `#homeRing`/`#homeFill`, при 100% — зелёное), список задач дня `#homeTasks` (строки `.trow`:
  эмодзи из начала текста — в иконку, время и «далее» / «время прошло» / «каждый день», нажатие на строку отмечает задачу;
  без задач — «Составьте распорядок дня» с кнопкой в календарь), три числа (дней подряд, задач за 7 дней, вес), плитки
  «Календарь» и «Добавки», совет дня. Главная перерисовывается при каждом показе вкладки.
- Вкладка «Питание» сверху вниз: «Добавить еду» (фото; под ними поиск `.fsearch` «🔍 Или найдите продукт по названию» —
  `#fSearch`, без запроса список пуст, с запросом до 6 результатов, выбор очищает поиск; штрихкод вручную — свёрнуто), карточки
  результата (`#aiCard` по фото, `#fres` из поиска/штрихкода), «Баланс КБЖУ» (шкалы `#mxList`, под ними подсказка «чего не хватает» `#insight`, внизу свёрнуто `#normFold` «Норма: N ккал в день ·
  изменить» — калории и цели БЖУ; отдельной карточки нормы нет), дневник.
  Приём пищи выбирается в карточке результата (`#aiMeal`, `#frMeal`, `mealChips`); при каждом открытии — по времени суток
  (`mealNow`); кнопки «Добавить в обед · N ккал» / «Добавить в обед».
- Календарь: сверху карточка «Надиктовать планы» `#vCard` (задачи голосом): `vStart` — микрофон через getUserMedia +
  AudioContext/ScriptProcessor, до 25 с (`VMAX`), уровень и таймер; `vFinish` → `vEncode` (16 кГц, 16 бит, base64) → action
  `voice` с `today`/`now` по часам телефона; ответ — `{text, tasks:[{text,date,time,end,place,daily}]}`; перед добавлением человек
  видит «Вы сказали…» и может поправить текст, дату, время, «Каждый день» или убрать задачу (`vRender`); `vSave` кладёт
  в `dayTasks[date]` или в `routine` (каждый день) и открывает в календаре первый день. Ошибки: нет доступа к микрофону,
  не расслышал (пустой текст), лимит 30 в день, нет связи. События Метрики: voice_ok, voice_add, voice_error.
- Повторы: задача в `routine` может иметь `wds` (дни недели 0–6), `from`, `until`, `skip` (дни-исключения); `repOn(r, key)` —
  есть ли она в этот день, `repLabel` — «по вт, чт до 18 мая». В форме календаря «Повтор»: Один раз / Каждый день / По дням
  (`#tRep`, `#tWds`, `#tUntil`, по умолчанию день выбранной даты и полгода). Удаление повторяющейся ✕: «на все дни?» →
  иначе «только в этот день?» (`skip`). Голос: приложение шлёт `existing` (`vExisting`: распорядок + разовые на 60 дней),
  сервер возвращает `remove` — в разборе строки «🗑 Убрать: …» с галочкой (`vRemoves`), у новых задач — повтор и дни.
- У задачи может быть место/адрес `place` (в `routine` и `dayTasks`; поле `#tPlace` в форме календаря, `.vpl` в разборе
  голоса — сервер достаёт его из речи). Показ — `placeHtml` («📍 …», в календаре, на главной и в ответах Арни), нажатие —
  `openMap` (Яндекс Карты через `tg.openLink`); на главной нажатие на адрес не отмечает задачу.
- У задачи может быть время окончания `end` (только вместе с `time` и позже него): поле «Конец» `#tEnd` в форме календаря
  (проверка «Конец должен быть позже начала»), «Конец» в разборе голоса (сервер понимает «с 7 до 9», «на 2 часа»).
  Показ — `tRange` («19:00–21:00»). На главной: между началом и концом — «идёт сейчас» (и подсветка), «время прошло» —
  после конца (или после начала, если конца нет).
- Данные пользователя — в localStorage (ключи `fithub_*`, например `fithub_lifts` — веса по упражнениям,
  `fithub_theme` — тема), копия — в Telegram CloudStorage.
- Сервер: константа `AI_ENDPOINT` (облачная функция Yandex). Действия: chat, digest_now, feedback, invoice, premium,
  ref, reminders, seen, stat, technique, а также фото еды без action.
- Вкладка «Тренировка» (`renderPlan`): карточка тренировки дня `#tHero` (сегодняшний день плана, в день отдыха — ближайший,
  одна кнопка старта и переключатель «С ИИ-тренером / Без камеры» — `fithub_cam`), неделя плана `#wkDays` с отметками
  (если на неделе тренировок не осталось — следующая неделя). Порядок: карточка дня, «Разбор техники по видео» (`.tqbox`, строка
  `#tqCardBtn` раскрывает выбор упражнения `#tqCardList`), «Эта неделя» `#wkCard`. Плитки «Программа» и истории тренировок во вкладке
  нет (история — в профиле, `#workFold`; программа меняется в «Моих данных»).
  Готовых тренировок нет: только подобранный план (`myPlan`); без плана — одна тренировка «Всё тело» и кнопка подбора.
- Перенос тренировки на одну неделю: во вкладке «Тренировка» у невыполненного дня этой недели — «📅 Перенести на другой
  день» (`#thMove`, `moveRender`, `moveTo`): дни с сегодняшнего по воскресенье, занятый день — меняются местами, «↩ Вернуть
  по расписанию». Хранится в `fithub_moves` `{ "<понедельник>": { "my0": день недели } }`; `myPlans(off)` отдаёт `wd` с учётом
  переноса (`wd0` — по плану, `moved`), задача «🏋️ Тренировка: …» в календаре переезжает (`moveTask`). Следующие недели
  не меняются. Бот учитывает переносы: `remPost` шлёт `wmoves` (`wMoves`: `add` — новые даты, `skip` — освободившиеся),
  после переноса — сразу `seen`.
- Подбор программы: `openGoal()` без готовой программы открывает пошаговый мастер онбординга в режиме `openOnb("plan")`
  (данные профиля и прошлая цель подставлены, «Закрыть» ничего не меняет, итог ведёт во вкладку «Тренировка»);
  с готовой программой — лист «Моя программа» (`renderGoalResult`: цель, дни свёрнуто, питание, «Подобрать заново»).
  Старая форма подбора (`#goalForm`) скрыта. В мастере 7 целей и поле «своими словами» (`onbOwn`).
- Дни тренировок выбирает человек (в мастере и в «Моих данных»): `userData.wds` — дни недели (0 = вс), 2–6 штук;
  `userData.days` = их число. Без `wds` — дни по умолчанию `SCHEDULE[days]`. Хелперы: `schedOf`, `wdChips`, `wdToggle`,
  `wdNote` (подсказка про тренировки на всё тело подряд). При смене дней в профиле план пересобирается, включённые
  напоминания о тренировках переносятся на новые дни.
- Тип программы — в профиле «Мои данные» (`userData.split`: auto / fb / ul / ppl, «тяни-толкай» от 3 дней и без
  ограничений по плечам). Генератор: `SPLIT_BY`, `splitType`, `splitText`. Сохранение профиля с изменёнными условиями
  тренировок пересобирает план (`applyPlan(plan, true)` — начало 4-недельного цикла сохраняется).
- Разбор техники по видео: строка `.tqbox` во вкладке тренировок и блок в карточке упражнения (`tqSection`); `tqRun`
  вынимает 8 кадров (видео до 20 с), рисует позу (MediaPipe, `loadPose`), собирает коллаж и шлёт action `technique`.
  Последние 3 разбора по упражнению — в localStorage `fithub_tech`.
- Обновление: через 5 с после открытия и при возврате в приложение (не чаще раза в 10 мин) код сверяется с сайтом
  (встроенные `<script>` и `<style>`, `fetch(..., {cache: "reload"})`); при расхождении — плашка `#updBar`
  «Вышло обновление» → перезагрузка. Во время тренировки и онбординга не показывается. Ничего обновлять вручную не нужно.
- Статистика: `track(событие)` → Яндекс Метрика (113832857) и action `stat` в функцию. Для владельца (`IS_OWNER`, Telegram id
  5517755450) Метрика не грузится и `statAdd` ничего не шлёт — его заходы не портят цифры.
- Профиль сгруппирован: шапка (вес, с начала, тренировки, подряд), «Прогресс» (вес — открыт; 🔥 серия `#fireFold`,
  🏋️ тренировки за 14 дней `#workFold`, 🏆 достижения — свёрнуты, итог в строке), «Настройки» (Мои данные, Напоминания,
  🎨 Оформление `#themeFold`), «FitHub» (Premium, пригласить друга, отзыв, сводка для автора).
- Карточка «Сводка для автора» (id `ownerCard`) видна только владельцу (Telegram id 5517755450).
- Арни: чат с ИИ через action `chat`; заготовленные ответы — массив `RULES`, функция `localAnswer`.

## Как выкладывать
Правка → `node tests/smoke.js dark` и `node tests/smoke.js light` (Playwright, iPhone 13, Telegram и сервер подменены;
15 проверок: путь новичка, вводная тренировка, еда по фото, голосовые задачи с повтором и «убери», задача по дням, профиль,
без ошибок в консоли; код выхода 1 при поломке, скриншоты в `tests/out-<тема>/`) + своя проверка новой функции → коммит
и push в main → проверить, что https://epl1r.github.io/FitHub/ отдаёт новую версию.
